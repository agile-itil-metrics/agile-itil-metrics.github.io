# บทนำส่วนที่ 3: ตัวชี้วัดเซอร์วิสเดสก์ เหตุขัดข้อง และคำขอ

**ตัวชี้วัดเซอร์วิสเดสก์ เหตุขัดข้อง และคำขอ แสดงให้เห็นว่าการสนับสนุนและการกู้คืนบริการทำงานได้ดีเพียงใดสำหรับผู้ใช้บริการ เพื่อให้คุณปรับปรุงประสบการณ์ในการขอความช่วยเหลือ ไม่ใช่แค่ปรับให้รายงานดูดี**

ส่วนนี้ของหนังสือคือจุดที่ผู้ใช้ได้พบกับบริการจริง ผู้ที่ลงชื่อเข้าใช้ไม่ได้ ลูกค้าที่สั่งซื้อไม่สำเร็จ และพนักงานที่ต้องการแล็ปท็อปเครื่องใหม่ ล้วนเข้ามาหาองค์กรผ่านเซอร์วิสเดสก์ การแจ้งเตือนจากระบบเฝ้าติดตาม พอร์ทัลบริการด้วยตนเอง หรือข้อความแชต สิ่งที่เกิดขึ้นต่อจากนั้นเป็นตัวกำหนดว่าพวกเขาจะประเมินบริการทั้งหมดอย่างไร ตัวชี้วัดในด้านนี้อธิบายประสบการณ์ดังกล่าวจากสองด้าน ได้แก่ องค์กรกู้คืนบริการได้เร็วและดีเพียงใดเมื่อมีสิ่งขัดข้อง และองค์กรดำเนินการตามคำขอตามปกติของผู้คนได้อย่างเชื่อถือได้เพียงใด

ใน ITIL 4 การจัดการเหตุขัดข้องและการจัดการคำขอบริการเป็นแนวปฏิบัติที่แยกจากกัน และเซอร์วิสเดสก์เป็นจุดติดต่อสำหรับทั้งสองอย่าง ทีมที่ทำงานแบบคล่องตัวและดูแลสิ่งที่ตนสร้างเองมักจัดการงานเดียวกันนี้ผ่านเวรเรียกฉุกเฉินและคิวงานที่ใช้ร่วมกัน ไม่ว่าจะเป็นแบบใด ปัญหาในการวัดผลก็คล้ายกัน จำนวนขึ้นอยู่กับวิธีจัดหมวดหมู่งาน เวลาขึ้นอยู่กับจุดที่นาฬิกาเริ่มและหยุดนับ และค่าเฉลี่ยซ่อนความล่าช้ายาวนานที่ผู้ใช้จดจำได้ นิสัยด้านสถิติที่กำหนดไว้ในส่วนที่ 1 ใช้ได้ตลอดทั้งส่วนนี้ (ดูหัวข้อ 1.6 “ความรู้ด้านสถิติสำหรับตัวชี้วัดบริการ”)

ตัวชี้วัดด้านการสนับสนุนยังถูกบิดเบือนได้ง่ายเป็นพิเศษ เดสก์อาจปิดตั๋วได้เร็วขึ้นด้วยการปิดก่อนเวลาอันควร และอาจลดเวลาในการจัดการด้วยการเร่งรัดผู้ติดต่อ ทีมอาจลดจำนวนเหตุขัดข้องด้วยการจัดประเภทใหม่ให้เป็นคำขอ ดังนั้นแต่ละหัวข้อในส่วนนี้จึงระบุพฤติกรรมที่ตัวชี้วัดให้รางวัล พฤติกรรมที่ตัวชี้วัดซ่อนไว้ และมาตรการป้องกันที่ช่วยแยกความแตกต่าง (ดูหัวข้อ 1.2 “กฎของกูดฮาร์ตและจิตวิทยาของตัวชี้วัด”) ทุกตัวชี้วัดในที่นี้อธิบายทีม บริการ หรือระบบ ไม่มีตัวใดจัดอันดับเจ้าหน้าที่หรือผู้ตอบสนองรายบุคคล

## หัวข้อในส่วนนี้

- **3.1 ตัวชี้วัดเซอร์วิสเดสก์**: ปริมาณการติดต่อ การแก้ไขได้ในการติดต่อครั้งแรก การวางสายก่อนได้รับบริการ และเวลาในการจัดการ สิ่งที่แต่ละตัวให้รางวัลและสิ่งที่แต่ละตัวซ่อนไว้
- **3.2 ปริมาณและลำดับความสำคัญของเหตุขัดข้อง**: จำนวนเหตุขัดข้อง หมวดหมู่ ผลกระทบและความเร่งด่วน สัดส่วนลำดับความสำคัญ เหตุขัดข้องที่เกิดซ้ำ และการปรับปริมาณให้เป็นมาตรฐานเทียบกับการใช้งาน
- **3.3 เวลาตอบสนองและเวลาแก้ไขเหตุขัดข้อง**: เวลาในการตรวจพบ รับทราบ ตอบสนอง และแก้ไข ตัวชี้วัดเวลาเฉลี่ยและปัญหาทางสถิติของตัวชี้วัดเหล่านั้น และการใช้เปอร์เซ็นไทล์แทน
- **3.4 ตัวชี้วัดเหตุขัดข้องรุนแรง**: ความถี่ ระยะเวลา ผลกระทบต่อลูกค้า ความทันเวลาของการสื่อสาร และการดำเนินการตามข้อปฏิบัติจนเสร็จสิ้น
- **3.5 ตัวชี้วัดการดำเนินการตามคำขอบริการ**: เวลาในการดำเนินการ งานค้าง ปริมาณคำขอตามรายการในแคตตาล็อก และสัดส่วนระบบอัตโนมัติ
- **3.6 ตัวชี้วัดการจัดการความรู้**: การใช้บทความ การนำกลับมาใช้ซ้ำในการแก้ไข อัตราการเชื่อมโยง ความทันสมัย และตัวบ่งชี้ Knowledge-Centered Service (KCS)
- **3.7 ตัวชี้วัดบริการด้วยตนเองและระบบอัตโนมัติ**: การเบี่ยงเบนการติดต่อ ความสำเร็จของบริการด้วยตนเอง ความครอบคลุมของระบบอัตโนมัติ และผลของการเลื่อนงานไปทางซ้าย (shift-left) ต่อปริมาณและความซับซ้อน

## หัวข้อเหล่านี้สัมพันธ์กันอย่างไร

สี่หัวข้อแรกเป็นไปตามวงจรของการหยุดชะงัก การติดต่อเข้ามาที่เดสก์ ซึ่งเป็นประเด็นของหัวข้อ 3.1 (ดูหัวข้อ 3.1 “ตัวชี้วัดเซอร์วิสเดสก์”) การติดต่อที่แจ้งข้อบกพร่องจะกลายเป็นเหตุขัดข้อง ซึ่งหัวข้อ 3.2 (ดูหัวข้อ 3.2 “ปริมาณและลำดับความสำคัญของเหตุขัดข้อง”) นับและจำแนกตามผลกระทบและความเร่งด่วน จากนั้นหัวข้อ 3.3 (ดูหัวข้อ 3.3 “เวลาตอบสนองและเวลาแก้ไขเหตุขัดข้อง”) วัดว่าแต่ละขั้นตอนใช้เวลานานเท่าใด เหตุขัดข้องจำนวนน้อยที่ก่อให้เกิดความเสียหายร้ายแรงได้รับการกล่าวถึงแยกต่างหากในหัวข้อ 3.4 (ดูหัวข้อ 3.4 “ตัวชี้วัดเหตุขัดข้องรุนแรง”) เพราะความหายากและขนาดของเหตุเหล่านี้ทำให้ค่าเฉลี่ยทั่วไปชวนให้เข้าใจผิด

ตัวชี้วัดหลายตัวต้องมีคู่หูเพื่อให้ยังคงซื่อตรง ความเร็วที่เดสก์ เช่นเวลาในการจัดการในหัวข้อ 3.1 ควรอ่านควบคู่กับการแก้ไขได้ในการติดต่อครั้งแรกและการติดต่อซ้ำที่เกิดขึ้น เพื่อไม่ให้เข้าใจผิดว่าการรับสายที่รวดเร็วคือปัญหาที่ได้รับการแก้ไขแล้ว เวลาแก้ไขในหัวข้อ 3.3 ควรอยู่คู่กับเหตุขัดข้องที่เกิดซ้ำในหัวข้อ 3.2 เพราะการกู้คืนที่รวดเร็วแต่กลับล้มเหลวอีกหนึ่งสัปดาห์ต่อมาไม่ได้ช่วยผู้ใช้ สัดส่วนลำดับความสำคัญในหัวข้อ 3.2 ให้บริบทแก่ตัวชี้วัดเวลาทุกตัว การที่เวลาแก้ไขมัธยฐานเพิ่มขึ้นอาจสะท้อนว่าชนิดของเหตุขัดข้องที่เข้ามาเปลี่ยนไป ไม่ใช่ว่าการตอบสนองของทีมแย่ลง

คำขอและเหตุขัดข้องควรวัดเคียงคู่กันแต่ไม่ควรรวมกัน หัวข้อ 3.5 (ดูหัวข้อ 3.5 “ตัวชี้วัดการดำเนินการตามคำขอบริการ”) ครอบคลุมงานดำเนินการที่คาดการณ์ได้และทำซ้ำได้ ซึ่งเป้าหมายคือความพยายามต่อคำขอที่คงที่และลดลง งานเหตุขัดข้องคาดการณ์ไม่ได้ และเป้าหมายคือการกู้คืนที่รวดเร็วและยั่งยืน การรวมทั้งสองไว้ในค่าเฉลี่ยของคิวเดียวจะซ่อนปัญหาของทั้งสองฝ่าย ตัวชี้วัดการไหลของงานในส่วนที่ 2 ให้นาฬิการ่วมและขีดจำกัดงานระหว่างทำที่ป้องกันไม่ให้สองสายงานแย่งทรัพยากรกันจนขาดแคลน (ดูหัวข้อ 2.9 “งานปฏิบัติการและงานที่ไม่ได้วางแผน”)

สองหัวข้อสุดท้ายลงมือจัดการกับปริมาณที่หัวข้ออื่นวัดไว้ ความรู้ในหัวข้อ 3.6 (ดูหัวข้อ 3.6 “ตัวชี้วัดการจัดการความรู้”) ช่วยลดเวลาแก้ไขด้วยการให้ผู้ปฏิบัติงานคนถัดไปนำสิ่งที่คนก่อนหน้าเรียนรู้มาใช้ซ้ำ และเป็นแหล่งป้อนเนื้อหาบริการด้วยตนเองที่วัดไว้ในหัวข้อ 3.7 (ดูหัวข้อ 3.7 “ตัวชี้วัดบริการด้วยตนเองและระบบอัตโนมัติ”) การเบี่ยงเบนการติดต่อและระบบอัตโนมัติลดการติดต่อแบบง่ายที่มาถึงเดสก์ ทำให้งานที่เหลือสำหรับผู้ปฏิบัติงานเป็นส่วนผสมที่ยากขึ้น ควรคาดหวังการเปลี่ยนแปลงนี้ และเวลาในการจัดการอาจเพิ่มขึ้นตามมา จึงควรอ่านว่าเป็นการเปลี่ยนแปลงของส่วนผสมงาน ไม่ใช่ประสิทธิภาพที่ถดถอย

เหตุขัดข้องที่เกิดซ้ำจะกลายเป็นข้อมูลนำเข้าของการจัดการปัญหาในส่วนที่ 4
