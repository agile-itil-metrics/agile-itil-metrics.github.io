# IT 资产管理指标

**你无法支持、保护或合理地为你找不到的东西付费，所以要度量资产记录有多准确、多完整、多新，并养成把资产记录作为日常工作的副产品、而不是每年一次大扫除的习惯。**

## 概述与动因

每项服务都建立在东西之上：笔记本电脑、服务器、许可证、云账户、网络设备，以及附着其上的数据和合同。[IT 资产管理](https://en.wikipedia.org/wiki/IT_asset_management)（ITAM）是把财务、合同和库存职能结合起来，以支持 IT 环境的生命周期管理和战略决策的一组业务实践。它回答其他实践所依赖的问题。我们拥有什么？它在哪里？谁对它负责？它花费多少？它何时必须续期、打补丁或更换？

持续交付与 ITIL 在这片领域里相遇得有些别扭。持续交付软件的团队始终在创建和销毁基础设施：容器、虚拟机、测试环境和云账户在几分钟内出现。一份季度电子表格跟不上。ITIL 传统中的 ITAM 坚持记录、负责人和生命周期，这种坚持是对的，因为无人管理的资产，是安全缺口、浪费的金钱和合规失败滋生之处。敏捷的贡献，是采购、财务、安全和运维之间的持续协作，以及在资产被创建时通过流水线和基础设施即代码自动记录资产的实用习惯，使记录成为工作的副产品。

有三个术语在本主题中反复出现。

- **资产：**对组织有价值、并通过生命周期来管理的一个项目。在 ITAM 中，这包括硬件、软件、云资源、订阅，有时还包括数据。
- **资产记录：**描述一项资产的条目：它是什么、谁拥有它、它在哪里、处于什么状态、花费多少，以及与什么相联。
- **生命周期：**资产所经历的各阶段，通常是已请求、已采购、已接收、已部署、使用中、维护中、已退役和已处置。[产品生命周期](https://en.wikipedia.org/wiki/Product_lifecycle)的思维适用于每一类资产，笔记本电脑和云订阅有不同的阶段。

ITAM 与配置管理有重叠，后者跟踪各组件之间的关系，使你能理解变更的影响，接下来的主题依次讨论软件、硬件和配置（见主题 7.2，软件资产与许可证指标，主题 7.3，硬件资产生命周期指标，以及主题 7.4，配置与 CMDB 质量指标）。差别在于目的：资产管理强调所有权、成本和生命周期，而配置管理强调结构和依赖。同一份清单往往为两者提供输入。

大多数 ITAM 项目所引用的标准是 ISO/IEC 19770，这是一族关于 IT 资产管理体系的标准。按名称和范围引用它，并在依赖任何细节之前，从标准机构阅读它。本主题不复制其文本。

资产指标很容易被变成目标，而这些目标在纸面上很容易达成。清单可以显示 100% 的准确性，因为它只记录已知之物。[古德哈特定律](https://en.wikipedia.org/wiki/Goodhart%27s_law)的护栏适用：对照独立证据度量准确性，并把完美的数字视为更仔细去看的理由（见主题 1.2，古德哈特定律与指标心理学）。

## 关键原则

- **在变更的那一刻记录。**资产应当作为创建或移除它们的工作的一部分，进入和离开记录。
- **对照独立证据度量。**准确性意味着与现实一致，用记录本身之外的方法来检查。
- **每项资产都有负责人。**无人拥有的资产不会被打补丁、被合理地付费，或被退役。
- **让记录尽可能小。**捕获决定所需的字段，不多不少。
- **结合多个来源。**发现工具、采购、财务、身份和云账单，各自看到资产的一部分。
- **跨职能协作。**采购、财务、安全和运维共享记录及其质量。
- **把缺口视为信息。**未能说明下落的资产是需要理解的发现，不是需要隐藏的失败。

为每一类说明"资产"的范围。笔记本电脑、虚拟机、订阅和许可证是不同的，记录字段和证据也不同。记录时间从造成变更的事件开始，比如货物收到、一次流水线运行或一次订阅开始，并在登记册反映它时停止。排除有意处于范围之外的资产，比如短暂存在的测试容器，并把它们作为一个排除类别列在登记册中。

## 建议

### 决定你在管理什么

**1. 列出重要的资产类别及其原因。**从承载成本、风险或法律义务的那些开始：终端用户设备、服务器和云账户、网络设备、软件许可证和订阅，以及关键数据存储。对每一类，写下记录必须支持的决定：打补丁、续约、审计、更新换代、处置。跳过没有任何决定需要的类别。

**2. 定义最少字段。**对每一类，选择决定所要求的少数几个字段：标识符、类型、负责人、位置或账户、状态、取得和结束日期、成本中心，以及与其所支持的服务的链接。准确的简短记录，比陈旧的冗长记录更有价值。把定义记录在指标登记册中。

**3. 为每个类别和每项资产指定负责人。**类别负责人设计记录和流程。资产负责人是对使用中的资产负责的个人或团队。在资产共享时，使用团队而不是个人，并保持目录最新，使人员离职不会让资产成为孤儿。

### 在工作进行时捕获资产

**4. 在流水线中登记资产。**在基础设施由代码创建之处，让流水线在创建和移除时写入登记册。这使记录时间接近于零，并使登记册与代码一致。持续交付变更的敏捷实践支持这一点：如果每次部署都更新记录，记录就很少出错。

**5. 把采购与登记册联系起来。**对购买的硬件和软件，让采购订单或订阅的创建触发记录，让收货或激活触发状态变更。针对实物商品的[库存管理](https://en.wikipedia.org/wiki/Inventory_management)实践，为接收、存放和发放物品提供了有用的模式。在采购发生在采购部门之外之处，比如团队用信用卡订阅，增加对费用数据的月度检查。

**6. 把发现用作检查，而不是记录。**发现工具扫描网络和云账户，并报告它们所发现的。它们善于告诉你存在什么，而不善于告诉你谁拥有它或为什么。用它们来检测缺失的和未知的资产，并与登记册比较。把一个来源与另一个来源匹配的步骤，是一种[对账](https://en.wikipedia.org/wiki/Reconciliation_(accounting))，也就是会计用来比较两组记录的同一思想。

**7. 在创建时打标签。**要求每个云资源上有负责人和服务标签，每个物理设备上有标签。像条形码和射频标签这样的[资产跟踪](https://en.wikipedia.org/wiki/Asset_tracking)方法，有助于管理仓库和办公室里的实物。没有标签的资源是给负责人团队的发现，作为运营的正常部分来处理。

### 诚实地度量

**8. 用随机样本审计。**每季度从登记册中随机抽取一份资产样本，并对照证据检查它们：找到设备、检查资源、确认负责人。然后反方向抽取一份样本，从发现结果和采购数据中抽取，检查每一个是否出现在登记册中。两个方向揭示不同的缺口。按类别分别报告准确率。

**9. 随时间观察数据质量。**记录的完整性、准确性和及时性，是[数据质量](https://en.wikipedia.org/wiki/Data_quality)的各个方面。按字段和类别跟踪趋势，并看哪些字段漂移最快。负责人和位置的漂移是正常的，也告诉你该在哪里自动化。

**10. 报告缺口。**除了头条准确率，也显示未能说明下落的资产、无主占比和未核对的项目。隐藏其例外的报告，是一份关于报告的报告。为每一类缺口指定负责人和日期。

### 闭合回路

**11. 像创建资产那样有意地让资产退役。**处置也需要记录：日期、方法，以及对于存放过数据的设备，数据已被擦除的证据。[监管链](https://en.wikipedia.org/wiki/Chain_of_custody)记录显示谁在何时经手一项资产。仍在登记册上的已退役资产会夸大成本并使审计混乱。

**12. 在日常决定中使用记录。**打补丁、续约、安全响应和预算，应当读取登记册。当人们使用它，他们就会修复它。当登记册只用于审计，它就会衰减。与依赖它的团队一起评审登记册的使用，并先修复他们抱怨的字段。

## 操纵途径与护栏

| 指标 | 被操纵的方式 | 配套的护栏指标或实践 |
| --- | --- | --- |
| 清单准确率 | 对容易的资产抽样；只在清理之后审计；以更少的字段计为匹配 | 由团队之外的人抽取随机样本；固定的字段清单；从两个方向抽样 |
| 发现覆盖率 | 把"预期资产"收窄到发现工具能看到的；排除难以扫描的网络 | 记录排除项；与采购和云账单比较 |
| 核对率 | 选择一个派生自第一个来源的第二来源；在薄弱的键上自动匹配 | 使用真正独立的来源；手工抽查匹配 |
| 无主资产占比 | 指派一个笼统的团队作为负责人；填入占位的人 | 由笼统团队拥有的资产计数；负责人确认抽样 |
| 生命周期阶段完整性 | 填入默认日期；把每项资产都设为"使用中" | 在审计中将阶段与证据比较；查看年龄分布 |
| 记录时间 | 倒填变更事件；把事件时间记录为记录时间 | 与源系统的时间戳比较；编辑的审计轨迹 |
| 未能说明下落的资产率 | 未经批准就注销资产；把它们重新归类为已处置 | 处置的批准和证据率；将注销与财务记录比较 |

健康的读数是一个因诚实的理由而保持在 100% 以下的准确率数字，可见且在缩小的缺口，在被询问时确认其资产的负责人，以及人们用来作出决定的记录。

## 权衡：利弊

| 做法 | 优势 | 劣势 |
| --- | --- | --- |
| 自动登记 | 快速、一致、工作量低 | 需要工程；会漏掉流水线之外的东西 |
| 手工登记 | 灵活，适用于任何东西 | 缓慢、易错、会衰减 |
| 由发现驱动 | 发现未知之物 | 无法提供所有权或目的 |
| 由采购驱动 | 捕获成本和合同 | 漏掉影子采购和免费层级 |
| 严格控制采购 | 记录强 | 拖慢团队；鼓励变通办法 |
| 轻度控制加检查 | 快速；依赖信任 | 有更多缺口要发现和修复 |
| 大的记录模式 | 丰富的报告 | 难以保持准确 |
| 小的记录模式 | 易于维护 | 分析有限 |

文字化的答案是，在基础设施是代码之处自动登记，把发现和账单数据用作独立检查，并保持记录小巧。信任团队创建他们需要的东西，请他们为其打标签，并通过抽样来核实。

## 与团队讨论的问题

**1. 如果明天我们必须找出与最重要服务相联的每一项资产，需要多久？**
挑一项服务，从登记册和其他来源追溯它的资产。为这次练习计时，并记下缺口。主持人应记录哪些来源一致，哪些不一致。结果显示登记册是一个工作工具，还是一份文档。

**2. 哪些资产是在这个房间里没人知道的情况下被创建的？**
想想云账户、订阅、测试环境和在采购之外购买的设备。问它们会如何显现。交谈会找出漏洞。约定本季度加入对账的一个独立证据来源。

**3. 谁拥有我们今天拥有的资产？我们怎么知道它们仍然存在？**
抽取一份资产样本，请指名的负责人确认。注意有多少负责人已更换角色或已离开。决定目录和登记册将如何保持同步，例如在有人离开时自动检查。

**4. 我们如何审计自己的登记册，而不是给自己的作业打分？**
讨论谁抽取样本、谁检查它。问如果结果很糟会怎样。主持人应探究人们是否觉得安全地报告一个糟糕的数字，因为不安全的审计会产生好看的数字。

**5. 我们记录了哪些没人使用的东西？**
列出登记册中的字段，问每一个被哪些决定使用。没有使用者的字段是移除的候选。被使用但不可靠的字段是自动化的候选。约定两项改变。

**6. 在"不再需要"和"消失"之间，一项资产会经历什么？**
追溯一台已退役的设备或一项已停用的服务。谁确认数据已被擦除？记录何时关闭？这条路径上的缺口，是成本、风险和审计发现累积之处。

## 四种视角

### 产品与交付团队

交付团队创建了大部分新资产，除非自动化，否则他们把记录工作感受为摩擦。他们应当把资产记录视为环境完成定义的一部分，让流水线登记它们所创建的东西，并用负责人为资源打标签。当他们需要找出成本、打补丁或让一个环境退役时，他们受益于准确的记录。

### 服务与运维团队

运维团队依赖登记册进行打补丁、事件响应和容量管理。他们应当把发现与登记册对账，追查无主资产，并把缺口作为发现来报告。他们还掌管实物处理：接收、镜像、存放和处置，其中监管链记录很重要。

### 领导层与治理

领导层和审计员依赖资产数据进行成本控制、安全保证和合规。他们应当要准确率的方法和缺口清单，而不只是头条数字，并为登记的自动化出资。治理应当期望登记册在决定中被使用，并对所报告的 100% 抱以怀疑。

### 客户与用户

用户在设备到货即可使用、需要时许可证就在、丢失的笔记本电脑得到妥善处理时，体验到资产管理。他们对入职和设备的反馈，是该流程在实践中如何运作的证据（见主题 6.4，用户与员工体验）。他们也有一个角色：在设备移动或离开时告诉 IT。

## 实践：一个敏捷 ITIL 示例

一家中型物流公司的 IT 部门支持约 2,400 名员工，并在云基础设施上运行一个产品平台。以下数字是示意数字。

一次内部审计要求提供公司拥有的设备和云资源的数量。登记册显示有 3,100 台终端用户设备和 1,850 个云资源。资产经理决定在报告这些数字之前先检验。她从登记册中随机抽取 100 台设备的样本，发现其中 87 台在所有四个约定字段上相符，准确率为 87%。从另一个方向，她从终端管理工具中抽取 100 台设备，发现其中 94 台在登记册中。云资产的发现覆盖率为 82%，因为项目团队创建的三个账户没有接入发现工具。把云账单导出与登记册对账，匹配了 71% 的计费资源，不匹配的大多是没有标签的测试环境。无主资产占比为 9%，其中三分之一由已离职的人拥有。

团队与产品团队和财务一起作出四项改变。流水线模板现在登记每个新环境，并要求负责人和服务标签。月度云账单与登记册对账，没有标签的资源报告给账户负责人。每月检查把人员目录与资产负责人比较，并在有人离开时向经理发送清单。仓库的收货当天就触发登记册更新。他们还改变了报告方式：审计摘要显示来自两个抽样方向的准确率、缺口清单和无主占比。

两个季度后，来自登记册样本的准确率为 93%，云资产的核对率为 90%，无主占比为 3%。财务负责人要求给董事会一个单一的"清单准确率"数字。资产经理提供该数字及方法和缺口清单，并拒绝报告 100% 的目标，解释说目标是保持缺口可见并在缩小。该决定被记录下来，团队指出，来自更好方法的较低数字，比先前未经核实的数字更有用。

## 行业视角

**初创企业。**可能没有正式的登记册，只有云账户和几台笔记本电脑。保留一份带负责人的简单清单，从一开始就为云资源打标签，并每月评审清单。在你知道需要回答什么问题之前，避免购买平台。

**小型企业。**一位管理员可能处理一切。如果有人每年两次对照采购检查，带几个字段的电子表格可以起作用。注意容易被遗忘的许可证和订阅，以及存放过数据的设备的处置。

**大型企业。**规模需要自动化、清晰的类别负责人，以及跨若干来源的对账。预期收购会带来陌生的资产，并计划一种标准的方式，使其纳入同一份记录。与财务就资产会计对齐，包括[固定资产](https://en.wikipedia.org/wiki/Fixed_asset)如何资本化和折旧，并约定 IT 登记册和财务账簿必须在哪里吻合。

**政府与公共部门。**公共机构面临审计、采购规则和记录义务，并且设备上常存放敏感数据。保留处置的证据，记录监管链，并使登记册与所要求的资产报告对齐。把登记册视为审计证据的一部分（见主题 8.3，合规与审计指标）。

## 商业论证：动机、投资回报与总拥有成本

成本包括设计记录的时间、（如果你没有）用于发现和对账的工具、在流水线中登记资产的工程工作量，以及抽样和修复的例行工作量。许多组织已经拥有发现和终端工具。一个适度的团队就可以运行这个项目，一旦登记自动化，持续成本就很低。

回报是避免的浪费和降低的风险。准确的记录减少为未使用的订阅和资源付费，加快事件响应和打补丁（因为你知道存在什么），并削减审计工作量。避免宣称来自已发布研究的具体百分比节省。度量你自己的基线：无主云资源的数量及其每月成本、回答一个审计问题的时间，以及已付费却未使用的许可证。也要计入风险的成本：未知的服务器是安全暴露，存有数据的丢失设备有通知成本。成本的财务处理见本部分后面（见主题 7.5，服务成本与单位经济）。

## 反模式与陷阱

- **年度大扫除。**一年一次的大工程在几周内就会衰减。持续记录，并每季度抽样。
- **只审计登记册。**它只证明登记册与自身一致。从独立证据出发，两个方向都抽样。
- **完美的分数。**100% 的数字通常意味着范围狭窄或证据薄弱。看看排除了什么。
- **负责人字段填成团队的笼统名称。**它看起来完整，却没有用。把笼统的所有权计为缺口。
- **字段太多。**人们用默认值填写它们。让记录保持在决定所需的范围内。
- **先有工具，后有流程。**没有所有权和生命周期规则的发现平台，会产生更大的混乱。先决定问题。
- **因缺口而惩罚团队。**他们会隐藏资产。把缺口视为发现，并修复原因。
- **忘记处置。**仍留在登记册上、或未留擦除记录就离开的已退役资产，会造成成本和风险。

## 检查清单

- [ ] 列出资产类别及每类记录所支持的决定。
- [ ] 每类的最少字段已定义，并记录在指标登记册中。
- [ ] 每个类别和每项资产都有具名负责人，并对照目录保持最新。
- [ ] 流水线用负责人和服务标签登记新基础设施。
- [ ] 采购和订阅创建触发资产记录。
- [ ] 发现和账单数据每月与登记册对账。
- [ ] 每季度从两个方向审计一份随机样本。
- [ ] 带负责人和日期的缺口清单与准确率数字一起公布。
- [ ] 处置有记录的方法和数据擦除的证据。
- [ ] 移除未使用的字段；登记册在日常决定中被使用。

## AI 提示词

**设计最少的资产记录。**

```text
我们在[组织类型]中管理这些类别的 IT 资产：[清单]。我们的资产数据必须支持的决定有：
[清单，例如打补丁、续约、审计、更新换代、处置]。请对每个类别，提出记录的最少字段、
每个字段应由哪个来源提供，以及如何对每个字段进行独立验证。不要编造监管要求。列出你的
假设，以及我应当与财务、安全或法务确认的任何事项。
```

**规划双向的审计样本。**

```text
我们的登记册包含跨[类别]的[数量]项资产。我们还有发现数据、采购数据和云账单数据。请设计
一次季度审计，用从登记册和其他来源抽取的随机样本，说明每个样本为得到有用的读数应有多大
（解释理由，但不要夸大精确度）、要记录什么，以及如何诚实地报告准确率和缺口。列出你的
假设。
```

**分析一次对账的结果。**

```text
我们把登记册与[来源]对账，发现：匹配[数量]、仅在登记册中[数量]、仅在来源中[数量]。这是
每一组的例子及我们持有的字段：[粘贴匿名化的例子]。请建议每种不匹配的可能原因、哪些容易
修复、哪些需要流程变更，以及首先应检查什么。不要假定数据无法支持的原因。列出你的假设。
```

**起草离职与调动检查。**

```text
请起草一个简单的月度流程，使用人员目录和资产登记册，找出其负责人已离职或已更换角色的
资产。包括步骤、谁收到清单、重新指派允许的时间、无人响应时怎么办，以及如何记录结果。
背景：[工具和团队规模]。列出你的假设和我应当核对的隐私考虑。
```

## 关键要点

- 在变更的那一刻记录资产，最好通过流水线和采购，使登记册成为工作的副产品。
- 对照独立证据度量准确性，从两个方向抽样。
- 每项资产都需要负责人，无主资产是发现。
- 保持记录小巧，并使其在日常决定中有用。
- 报告缺口，而不只是头条数字，并怀疑完美的分数。
- 像规划创建那样仔细地规划处置。
